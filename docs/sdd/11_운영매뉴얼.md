# 11. 운영 매뉴얼

## 설치 방법
1. 설치 파일을 실행한다.
2. 설치 경로를 선택한다.
3. 바탕화면 바로가기 생성 여부를 확인하고 설치를 완료한다.

## 발송 방식 선택 가이드

회사 메일이 Gmail로 통합되었지만, 회사 정책에 따라 사용 가능한 발송 방식이 다를 수 있다. 일반적으로는 앱 비밀번호 방식이면 충분하다.

| 환경 | 권장 방식 | 비고 |
|---|---|---|
| 일반적인 회사 Gmail | **Gmail (앱 비밀번호) — 권장** | 2단계 인증 + 앱 비밀번호 등록만 필요. 가장 단순. |
| 앱 비밀번호 차단된 환경 | Gmail (OAuth) | IT 팀과 협업해 Google Cloud OAuth 클라이언트 1회 등록 후 사용. |
| Outlook 이 회사 Gmail 에 연결돼 있는 PC | Outlook | 추가 설정 없이 동작. |
| SMTP/OAuth 모두 차단 또는 일시적으로 막힌 경우 | EML 초안 파일 저장 | 인증 없이 .eml 파일로 저장해 사용자가 직접 발송. |

## 최초 1회 설정 — Gmail (앱 비밀번호, 권장)

1. 프로그램을 실행한 뒤 상단 **메일 설정** 탭으로 이동한다.
   - 자격증명이 비어있으면 처음 실행 시 자동으로 메일 설정 탭이 열린다.
2. Google 계정에서 **2단계 인증**을 활성화한다 (https://myaccount.google.com/security).
3. **앱 비밀번호**를 발급받는다.
   - 메일 설정 탭의 "Gmail 앱 비밀번호 발급 페이지 열기" 버튼을 누르면 발급 페이지(`https://myaccount.google.com/apppasswords`)로 바로 이동한다.
   - 앱 이름을 적당히 입력하고 비밀번호를 만들면 16자리 문자열이 화면에 표시된다.
   - 발급된 16자리 비밀번호(예: `abcd efgh ijkl mnop`)를 그대로 붙여넣어도 공백은 자동 제거된다.
4. 사용자 이름(메일 본문에 표시) · Gmail 주소 · 앱 비밀번호를 입력한다.
5. **Gmail 연결 테스트** 버튼을 눌러 로그인 가능 여부를 확인한다.
6. **설정 저장** 버튼을 눌러 정보를 저장한다.

## (참고) Gmail OAuth 설정 — 앱 비밀번호 차단 환경 전용

일반 사용 환경에서는 필요 없다. 회사 정책으로 앱 비밀번호가 막힌 경우에만 IT 와 협업하여 진행한다.

### 관리자(IT) 작업 (1회)
1. https://console.cloud.google.com/apis/credentials 접속 (메일 설정 탭의 "Google Cloud Console 열기" 버튼 사용).
2. 프로젝트가 없으면 새로 생성한다.
3. "OAuth 동의 화면"을 설정한다. 사내 전용이면 **Internal** 로 설정.
4. "사용자 인증 정보 만들기" → "OAuth 클라이언트 ID" → 애플리케이션 유형 **데스크톱 앱**.
5. 발급된 Client ID, Client Secret 을 사용자에게 전달.

### 사용자 작업 (1회)
1. 메일 설정 탭에서 "Gmail Google 로그인 (대체 옵션)" 박스를 펼친다.
2. Client ID / Client Secret 을 붙여넣는다.
3. **Google 로그인** 버튼을 누른다.
4. 브라우저가 열리면 본인 회사 Gmail 계정을 선택하고 권한을 허용한다.
5. "기본 발송 방식"을 "Gmail (Google 로그인 / OAuth)" 로 바꾼다.
6. **설정 저장** 으로 마무리한다.

## 실행 방법 (업무 흐름)
화면 상단에 표시되는 진행 순서를 따라가면 된다.

1. **① 소스 파일 추가** — 사업장별 자재유형별수불집계 파일을 등록한다. 사업장명은 파일명에서 자동 추출되며 필요 시 수정한다.
2. **② 거래처 불러오기** — 등록한 소스 파일에서 거래처 목록을 추출한다.
3. **③ 거래처 선택** — 검색창과 체크박스로 발송할 업체를 다중 선택한다.
4. **저장 폴더 선택** — 산출물 저장 위치를 지정한다. 직전 사용 폴더가 자동으로 채워진다.
5. **④ 산출 실행** — Excel/PDF 파일을 거래처별 폴더에 생성한다.
6. **⑤ 메일 발송** — 발송 대화상자에서 발송 방식을 확인하고 발송한다.
   - 회신 요청일은 다음 주 금요일이 기본값으로 채워진다.
   - "EML 초안 파일로 저장" 선택 시 산출물 폴더 하위 `_메일초안_EML/` 에 .eml 파일이 저장된다.

## 사용 규칙
- 소스 시트는 `Sheet1`이어야 한다.
- 필수 컬럼은 `거래처명`, `자재코드`, `색상`이며 `자재명`은 없으면 빈칸 처리된다.
- `보관 수량`은 프로그램이 채우지 않는다.
- 동일 파일이 있으면 덮어쓰기 여부를 확인한다.
- 메일 발송은 첨부파일(Excel + PDF) 2개가 모두 존재해야 진행된다.

## 장애 대응
- 파일 읽기 오류 시 파일 손상 여부와 시트명을 먼저 확인한다.
- 필수 컬럼 누락 시 소스 파일 헤더명을 확인한다.
- PDF 생성 실패 시 출력 권한, 경로, PDF 엔진 상태를 확인한다.
- Gmail 앱 비밀번호 인증 실패 시 다음을 순서대로 확인한다.
  1. Google 계정의 2단계 인증이 켜져 있는지
  2. 일반 비밀번호가 아닌 **앱 비밀번호**를 사용했는지
  3. 입력한 Gmail 주소가 올바른지
  4. 회사 정책으로 앱 비밀번호가 차단되었다면 → OAuth 또는 EML 방식 사용
- Gmail OAuth 인증 실패 시:
  1. 메일 설정 탭에서 "연결 해제" 후 "Google 로그인"을 다시 시도.
  2. 회사 OU 정책에서 해당 OAuth 클라이언트가 차단되지 않았는지 확인 (관리자 협업).
- 모든 발송 방식이 막힌 비상 상황에서는 **EML 초안 저장** 모드를 사용해 발송한다.
- 일부 업체가 발송에서 제외되면 결과 화면의 "제외 내역"에서 사유를 확인한다(이메일 미입력 / 형식 오류 / 첨부파일 없음).

## 설정 항목
- 최근 사용 폴더 저장 (QSettings)
- 메일 설정 (SQLite app.db)
  - 사용자 이름, 기본 발송 방식, SMTP 호스트/포트/계정, OAuth Client ID, OAuth 연결된 계정 이메일
  - 제목/본문 템플릿 기본값
  - 거래처별 이메일 주소 (자동 저장)
- 자격증명 (Windows Credential Manager)
  - Gmail 앱 비밀번호
  - OAuth Client Secret
  - OAuth Refresh Token

## 인수인계 체크 포인트
- 양식 파일 위치
- PDF 생성 엔진
- 설치 패키지 생성 방법
- 사업장명 자동 추출 규칙
- Gmail 앱 비밀번호 정책 (담당자 교체 시 재발급)
- (OAuth 사용 시) Google Cloud Client ID/Secret 관리 정책
